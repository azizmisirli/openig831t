# DJI host analysis: static scope and limits

**SOURCE_SUPPORTED:** bounded static analysis of the DJI Mobile SDK 5.18.0 implementation found relevant dongle parsing, publication and cache paths. The public repository publishes independently written summaries, not SDK binaries, complete decompilation or disassembly. The official sample's use of LTEManager is a real API integration lead, but it does not prove behavior of every DJI desktop or aircraft host.

**SOURCE_SUPPORTED:** OLD and MULTI data can reach a normalized public state path. NEW has a separate format and public-state shape. Some equality/cache replacement behavior was identified, and a Mix characteristics filter affects publication in the reviewed path. **UNKNOWN:** actual arrival order, accepted source, active abstraction, final cache value, connection outcome or global identity policy.

**SOURCE_SUPPORTED:** the static active-path investigation closed at scoped gate C, meaning partly related implementation evidence without an established target runtime path. This is not a C-grade compatibility score and not an all-DJI conclusion. Internal abstraction names are not commercial product identifications.

## What does not count as acceptance evidence

- Registration entry is not successful registration or active routing.
- Callback entry is not parser acceptance.
- Publication entry is not a completed cache commit.
- CacheSet entry is not a finished store.
- Listener invocation or UI visibility is not an LTE connection.
- Generic equality or serialization is not an identity whitelist.

**UNKNOWN:** requirements for USB VID/PID/serial, AT/DMS identity, service-version tolerance, entitlement or server authorization on an actual target host. “Not proven” must not be rewritten as “not checked.” False/default/partial-decode values do not by themselves prove a remote producer rejected a modem.
